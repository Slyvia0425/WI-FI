# 呼吸模块：数据缺口排查与外部数据候选清单

核查日期：2026-10-29。只检查本地元数据、抽查文件结构、检索官方资料；
本轮未下载新数据、未联系作者、未训练/修改算法、未提交 GitHub。
“已找到官方说明”不等于“已下载验收”，未确认项不能当作已有能力。

## 1. 排查结论：不是所有场景都缺，而是独立性和真值不足

### 本地 CSI-Bench BreathingDetection

元数据共 100,000 个样本：sleep 80,580，empty 19,420；官方
train/val/test 为 70,000/15,000/15,000。这些是样本数，不能直接解释为
独立人员、原始录制次数或有效监测时长。

**已有风扇场景，不必为了同一批数据重新下载整个 CSI-Bench。**

| 场景标签 | sleep 样本 | empty 样本 | 说明 |
|---|---:|---:|---|
| LOS_FanOff | 3,884 | 3,884 | 可做现有开发场景对照 |
| LOS_FanOn | 3,884 | 0 | 本地缺少该组合的空房间样本 |
| NLOS_FanOff | 3,884 | 3,884 | 可做现有开发场景对照 |
| NLOS_FanOn | 3,884 | 3,884 | 已有“空房间＋风扇”负例 |

这些条目的 user 字段全部为 U23，且已分布在原 train/val/test 中。
empty 的 user 字段是数据来源标识，不表示房间里真的有人。
这些场景可以检验冻结模型的开发阶段表现，不能重新命名为全新独立测试。
现有 session 字段的唯一性也不能证明窗口之间没有源录制重叠。

按普通样本及七个风扇/标签组合抽查了 8 个 HDF5，均只有 `CSI_amps`
（300 个时间点），没有文件级属性，也没有同步呼吸参考或包级时间戳字段。
这是抽查范围，不是对全部 HDF5 的新全量审计。结合现有加载器，适合
呼吸证据/空房间检测，不应拼接独立十秒样本来评价三十秒呼吸率或连续性。

官方上游目前声明基准已更新至 Kaggle Version 12；本地版本来源尚未确认。
后续先记录/比较元数据、划分和文件哈希，不覆盖当前数据和 checkpoint。
新版本或同源新子任务不自动成为独立外部数据。
[官方上游与版本说明](https://github.com/guozhen-jenn-zhu/CSI-Bench-Real-WiFi-Sensing-Benchmark)。

### 本地 WiRe-Breath

已核查 467 个片段、85 个录制组、5 人、2 个房间；394 个三十秒窗口通过现有
时间质量要求，73 个保留排除。Quiet 240、Interference 227，均为有人呼吸
场景；有 CSI/参考各自的时间戳及参考波形。

它已反复用于错误分析和方案开发，且已确认同录制片段重叠，不能充当新独立测试。
`Interference` 不能改标成空房间、风扇或无呼吸。
[作者发布说明](https://github.com/Yunpeng-Ge/WiRe-Breath)。

本地 `data/` 目前只有上述两个数据目录，没有 MotionSourceRecognition。
机器可读结果：`outputs/data_gap_inventory_v1/inventory.json`。

## 2. 真正需要补的数据

| 优先级 | 缺口 | 当前覆盖与不足 | 新数据用途/验收重点 |
|---|---|---|---|
| P0 | 独立人员/录制的静止呼吸＋同步参考 | WiRe 已用于开发，不能再作新测试 | 检验冻结呼吸率估计器的外部误差 |
| P0 | 空房间＋周期设备干扰 | 本地 NLOS_FanOn 已有，但单一来源、无新独立性 | 外部误报压力测试；必须明确无人及设备状态 |
| P0 | 有人呼吸＋干扰＋同步参考 | WiRe 只有宽泛 Interference，难定位干扰机制 | 检查有效呼吸率覆盖与误差，而非一律拒绝 |
| P1 | 同场所的空/有人、设备开/关配对 | 本地部分组合存在，LOS_FanOn-empty 缺失 | 避免模型靠房间/设备差异猜标签 |
| P1 | 真实长连续记录及状态切换 | 现有回放不能替代独立连续采集 | 至少覆盖连续多个三十秒窗口；入离场/运动起止时间明确 |
| P1 | 人体大运动及恢复 | 运动标签不等于呼吸消失，也不必然等于率不可靠 | 有参考才能评定呼吸率可靠性；无参考仅作风险场景测试 |
| P2 | 新硬件、距离、遮挡、方位 | 当前设备域和场所覆盖有限 | 分硬件/场所/人员报告，保留域偏移信息 |
| P2 | 可验证的多天线相位数据 | 现有相位审计未支持简单处理，映射/标定信息不足 | 非当前优先项；没有标定信息不继续盲调 |

外部正常活动、机器数据通常不能填补“带同步呼吸参考的干扰”这一核心缺口。
本轮未确认有一个可直接下载、已满足上述所有条件的统一数据集。

## 3. 数据验收清单

### 所有数据均须先确认

- [ ] 作者/机构来源、固定版本/DOI、许可及使用条件；网页可见不等于许可已确认。
- [ ] CSI 是原始复数、原始幅度还是处理后的特征，处理步骤能否追溯。
- [ ] 时间单位、真实采样率、每条时长、包时间戳/丢包，以及是否已裁成短窗口。
- [ ] 人员、原始录制、日期、房间、设备、带宽、天线/子载波映射。
- [ ] 空房间、设备开关、运动等标签的具体定义；不靠文件名猜更细的语义。
- [ ] 来源是否与现有数据或其他候选重叠；同录制、多接收端和派生版本共同分组。
- [ ] 小样本格式验收成功后才考虑大体积下载；原始数据只读、记录校验值。

### 若要评价呼吸率，额外必须有

- [ ] 独立呼吸参考波形或可追溯的独立率标签；优先胸带/气流等参考波形。
- [ ] 参考与 CSI 的同步方法、时间轴及偏移/漂移说明。
- [ ] 至少能形成真实连续三十秒有效观测；不能重复或拼接独立短样本凑长度。
- [ ] 参考缺失或质量差要单独报告，不能用 CSI 预测给自己充当真值。

参考只给整段 BPM 时只能验证相应整段率，不能冒充逐窗参考。
只有“有人坐着”的标签不能评价 BPM；只有机器/活动标签也不能自动生成
`not_assessable` 的呼吸率真值。无人时不计算 BPM 误差，评价错误输出率。

## 4. 外部候选：按实际用途筛选，不按论文标题承诺

### A. Intel Wi-Fi CSI Respiratory Sensing Dataset：优先小规模资格核查

[官方 Zenodo v2](https://zenodo.org/records/20122379) 列出约 165.1 MB CSV，
包含 Empty、OneSitting、OneSittingOneWalking 等文件。适合首先排查
独立空场/有人/他人运动场景，**未确认有同步呼吸参考，不能承诺验证率误差**。
`IFcomputer` 的具体干扰机制也未核实，不能改叫“风扇”。

先看许可、字段和时间轴；页面的许可栏没有提供足够可核验文字，暂不标为许可验收通过。
CSV 的时间戳、时长、人员/录制映射及预校正含义仍待文件检查。
若资格通过，第一批只需同一个 20 MHz 系列：

1. `CSI_complex1_aligned_fixedPiOffset_20MHz_Empty_for_WiSENSE26Paper.csv`（约 6.8 MB）；
2. `CSI_complex1_aligned_fixedPiOffset_20MHz_OneSitting_for_WiSENSE26Paper.csv`（约 10.3 MB）；
3. `CSI_complex1_aligned_fixedPiOffset_20MHz_OneSitting_OneWalking_for_WiSENSE26Paper.csv`（约 5.0 MB）。

合计约 22.1 MB，以官方实际文件大小为准。不要同时下载相同场景的所有变体后
当作独立重复样本；须先检查派生/重叠关系。当前只核实了文件列表，没有下载或测模型。

### B. EHUNAM：机器/空场/人机共存补缺，先要目录，不先下整包

[作者仓库](https://github.com/GuillermoDiazSM/EHUNAM-dataset) 给出约 78 GB
`EHUNAM.zip` 及小于 1 MB 的 `Summary.xlsx` / `Summary.mat`，指向
[Figshare 数据 DOI](https://doi.org/10.6084/m9.figshare.28541225)。
仓库标明 CC BY 4.0。适合从索引筛空场、机器状态和人机共存记录；不是呼吸率
真值数据的替代。网页/仓库已核实，Figshare 页面本次访问受限，实际文件未验收。

[原始论文](https://www.nature.com/articles/s41597-025-06238-4) 说明有家电、
工业机器与多人场景。它不等同风扇数据，也未据此确认同步呼吸参考。
先核查目录能否筛到无人机器记录、相应对照、包时间戳和足够长的原始录制，
再决定具体文件。若只能整包下载，先评估存储，不立即下载 78 GB。

### C. VitalCSI：真人呼吸率外部验证的条件候选，需要申请

[作者论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC12788229/) 描述以鼻气流
作为参考的真人呼吸率实验；[机构存档的可用性声明](https://ora.ox.ac.uk/objects/uuid%3A4935e9bb-33d0-41e8-af97-eebb63e247b0/files/rrr172063w)
说明因隐私需向作者申请，不是已确认可直接下载的数据。

若取得授权，须进一步确认能否提供原始 CSI、同步参考、录制/人员编号及
数据使用条款。它更贴近“独立真人率验证”，但当前没有文件、没有申请/发邮件，
也不能把论文报告的结果视为我们算法的效果。

### D. NIST BreatheSmart：受控工程对照，不是真人独立验证

[NIST/Data.gov 官方目录](https://catalog.data.gov/dataset/raw-data-used-to-investigate-the-use-of-wi-fi-signals-to-monitor-human-respiratory-motion)
提供呼吸仿真人体的原始实/虚部 CSI、数据 ZIP 与 README 下载入口。
可作受控周期信号/装置条件测试，不可替代新人员、真实运动干扰或临床评估。
尚未读取下载文件中的时间轴、具体试验配置和真值形式，先验收 README 再决定。

### E. BS-Breath：有同步参考，但不是同制式 Wi-Fi，暂列次选

[KU Leuven 官方数据页](https://rdr.kuleuven.be/dataset.xhtml?persistentId=doi:10.48804/AYJUHX)
列有 3.51 GHz、64 天线、10 人、同步 MoCap 参考及约 11.7 GB
`data_single_person_wo_interf.zip`，CC BY 4.0。它是 cell-free massive MIMO
平台，不应直接称为商品 Wi-Fi 同域验证；公开包名也不是干扰场景承诺。
可以研究跨平台迁移，但不是当前最省成本的风扇补缺或即插即用测试首选。

### F. CSI-Bench MotionSourceRecognition：同源开发补充，不是独立外部验证

[官方结构](https://github.com/guozhen-jenn-zhu/CSI-Bench-Real-WiFi-Sensing-Benchmark)
含 Human/Pet/IRobot/Fan 类别，本地尚无该任务。可考虑只补任务 metadata/splits
与相应 Fan 样本；先查录制背景、是否无人、源数据重叠和数据发布许可。
Fan 类别表示运动来源，不自动意味着“房间中没有人”，也不提供呼吸率真值。

### G. 暂不作为直接下载首选的其他线索

- [eHealth CSI 原始机构说明](https://cris.ulima.edu.pe/es/publications/ehealth-csi-a-wi-fi-csi-dataset-of-human-activities/)
  描述多人物活动和空房间、访问需申请；所列生理参考为心率。
  [PulseFi 原文](https://arxiv.org/html/2510.24744v1) 也明确其使用的 eHealth
  版本缺少呼吸率标签，不能因为人数多就当作呼吸率训练/验证集。
- [HKU 教学仓库](https://github.com/hku-aiot-courses/lab_wifi_sensing) 提及
  PLUX 呼吸胸带数据，但课程用途、许可、OneDrive 链接与来源重叠均待确认，
  不直接复制课程代码或把课程测试数据视为正式独立基准。
- [Monostatic Intel 数据卡](https://huggingface.co/datasets/JessicaSanson/Wi-Fi_Monostatic_Human_Sensing_CSI_Intel)
  是静态呼吸/走动存在感知线索，但未确认呼吸参考；不优先于更小的 Intel 候选。
- 雷达、UWB 或普通 HAR 数据不能只改文件格式就算 Wi-Fi 呼吸率数据；不为凑数量下载。

## 5. 独立验证的使用规则（下载前确定）

1. 冻结当前幅度估计器、分类 checkpoint、检测阈值、输入映射与质量规则，记录哈希。
2. 新数据先作结构/同步/来源验收，不根据参考 BPM 改规则、筛好看的记录。
3. 若要继续开发，先按整个人员/原始录制/场所划出资格确认与封存评估部分；
   同次录制的不同接收器、重叠窗口、派生版本不可拆开。小数据不硬拆成伪独立大测试集。
4. 封存部分不调阈值、不训练；若用过结果指导修改，明确降为开发数据，不能反复叫独立测试。
5. 分开评价：空场/机器的错误呼吸输出率；有参考记录的 MAE、>5 BPM 错误、
   有效覆盖率、准确结果受损，以及按人员/录制等权指标。无参考记录不计算率误差。
6. 人在运动不等于不呼吸；未检测到呼吸不等于无人；没有呼吸证据不等于确诊呼吸暂停。

## 6. 建议执行顺序

**现在无需重训，也无需先下一个巨大数据集。**

1. 利用本轮已确认的本地 FanOn/FanOff 清单整理开发场景覆盖（本轮未重新测模型）。
2. 优先核查 Intel 小包的许可及三类 CSV 字段/真实时长，决定是否做冻结算法的外部存在感知压力测试。
3. 获取 EHUNAM 的小目录文件，选机器/无人/人机组合，避免盲下整包。
4. 真人呼吸率外部验证另走 VitalCSI 等有独立参考的获取渠道；联系作者需另行授权。
5. 若仍缺“有人＋指定干扰＋同步呼吸参考”，承认缺口，规划后续受控采集；不要用机器标签伪造真值。

只下载/验收不代表已补齐训练数据。是否进入训练应在数据身份、标签、同步和独立划分
确认后另行决定。当前模型、前端、数据与既有实验输出保持不变。
